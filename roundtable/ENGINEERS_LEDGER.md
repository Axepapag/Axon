## Heart Transformer sizing recommendation

Learned Heart Transformer tissue is required for semantic decoding, grounded interlingua transport, ambiguity detection and destination-rail encoding; deterministic Heart authority remains responsible for canonical validation/commit. The existing `64D / 2-layer / 4-head / 4096-FFN` translator is a valid first experimental baseline and possible permanent D64 specialist, not a credible final whole-Heart claim. It contains 1,173,879 trainable parameters; 4096 is a 64x FFN expansion, so the FFN is not tiny, while every attention/query state remains a real 64D bottleneck.

Head **sensory source** and head **internal dimension** are separate choices. A head can attend exact frozen 16D substrate cells while still using a 16D, 32D or projected 64D query/key/value space. Sentence-scale or episode-scale perception comes primarily from the slots/lens supplied to that head and its receptive field, not simply from making the head wider. First specialize equal-width heads by governed senses (exact substrate, referent/proposition, semantic qualifiers/intent, provenance/global roundtrip). Unequal head dimensions are a legitimate later experiment, preferably as separately normalized sensory-attention modules rather than by immediately replacing optimized multi-head attention.

Recommended bounded 64D comparison under matched data/compute: current `4 x 16D`; `2 x 32D`; and one experimental heterogeneous allocation such as `8D + 8D + 16D + 32D`. The heterogeneous candidate must prove a capability gain large enough to justify custom kernels, weaker batching efficiency and additional normalization/gating risk. A same-depth `1024D / 16 x 64D-head / 4096-FFN` instance of the present architecture has 42,250,359 parameters (161.17 MiB FP32 weights before gradients/optimizer/activations); it is possible later but not the correct first diagnostic on this machine.

Only the D64 exact+semantic rail/compiler exists today, and frozen tick images explicitly reject non-64 widths. There is no D128/D256/D512/D1024 compiler, codec or Heart core. More importantly, the curriculum label `rail_d64_v1` currently denotes synthetic readable text (for example, `State that Mira will run.`), not a real compiled D64 tensor dialect. Exact field-to-rail rendering should remain deterministic; mature learned conduction should use a shared grounded Heart interlingua plus a governed ingress/egress codec for every active rail width. A full independent Heart Transformer per rail is optional, but a verified exact compiler/lens and semantic/native-proposal codec per active width are not. This real D64 codec/vertical-slice gap must be closed before substantial Heart training.
